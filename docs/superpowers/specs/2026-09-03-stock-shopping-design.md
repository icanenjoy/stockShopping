# stockShopping 설계 문서

- 작성일: 2026-09-03
- 상태: 승인됨 (MVP 범위 확정)

## 1. 제품 정의

국내 주식을 쇼핑몰처럼 탐색하는 시뮬레이터. 사용자는 종목을 검색해 장바구니에 담고,
수량을 정하고, 현재가 기준 합계 금액을 확인한다.

핵심 아이덴티티는 **가격 변동을 "할인 / 가격 인상"의 언어로 번역해 보여주는 것**이다.
등락률을 숫자로 나열하지 않고, 취소선 정가와 할인 배지가 있는 상품 카드로 표현한다.

MVP에는 주문·체결·계좌·수익률이 없다. "이 조합을 사려면 지금 얼마인가"에만 답한다.

### 성공 기준

- 종목명으로 검색해 1초 안에 결과가 뜬다
- 담기 → 수량 조절 → 총액 반영이 즉시 이뤄진다
- 장바구니 총액이 실제 현재가를 반영한다
- 시세 API가 실패해도 총액이 화면에서 사라지지 않는다

## 2. 확정된 결정

| 항목 | 결정 | 비고 |
|---|---|---|
| 범위 | 장바구니 합산까지 | 2단계에서 모의 주문으로 확장 |
| 시세 소스 | 한국투자증권 KIS OpenAPI | 토스증권 오픈API와 비교 후 선택 |
| 시장 | 국내(KRX)만 | 미국 주식은 확장 과제 |
| 스택 | Next.js (App Router) + TypeScript | 단일 저장소, Route Handler가 백엔드 |
| 인증 | 없음 | 장바구니는 localStorage |
| 가격 갱신 | 조회 시점 갱신 + 장바구니 화면 폴링(5~10초) | |

### 시세 소스 선택 근거

토스증권 오픈API(2026-08-13 정식 출시)는 국내·해외 통합 API라 확장에 유리하지만,
신생 API라 막혔을 때 참고할 자료가 얇다. KIS는 자료와 커뮤니티가 성숙해 있어
문제 해결에 드는 시간이 예측 가능하다. 신생 API의 진짜 비용은 기능이 아니라
검색해도 답이 나오지 않는 시간이므로 KIS를 선택한다.

KIS가 제공하는 모의투자 서버는 선택 근거가 아니다. 2단계 확장은 자체 가상 현금으로
구현하므로 증권사 모의투자 서버를 쓰지 않는다.

어느 쪽이든 `PriceProvider` 뒤에 숨기므로 나중에 교체하는 비용은 낮다.

## 3. 아키텍처

```
[브라우저]
  ├ 검색 · 상품 카드 · 장바구니 (localStorage)
  └── /api/search, /api/quotes
        └ [Next.js Route Handler]
             ├ KisTokenManager   접근토큰 발급 · 캐싱 · 갱신
             ├ QuoteCache        종목별 5초 TTL
             └ PriceProvider     교체 가능한 인터페이스
                  └ KIS REST
```

### 왜 서버가 필요한가

KIS API는 브라우저에서 직접 호출할 수 없다. 앱시크릿이 노출되고 CORS도 막힌다.
따라서 "프론트 → 우리 서버 → KIS" 구조가 강제되며, 앱키·시크릿은 서버 환경변수로만
존재하고 브라우저로 내려가지 않는다.

## 4. 모듈 경계

### `PriceProvider` (인터페이스)

```ts
interface PriceProvider {
  search(query: string): Promise<StockSummary[]>
  getQuotes(codes: string[]): Promise<Quote[]>
}

interface Quote {
  code: string          // 종목코드
  name: string
  price: number         // 현재가
  prevClose: number     // 전일 종가
  high52w: number       // 52주 최고가 (= 쇼핑몰의 "정가")
  tradingHalted: boolean
  asOf: string          // 시세 기준 시각 (ISO)
}
```

구현체:

- `MockProvider` — 종목 마스터에서 표본을 뽑고 가격을 흔든다. 개발·테스트용
- `KisKrxProvider` — 실제 KIS 국내주식 시세
- `KisUsProvider` — 확장 과제 (미국 주식)

`MockProvider` 덕분에 KIS 앱키 발급을 기다리지 않고 전체 플로우를 완성할 수 있다.

### `KisTokenManager`

KIS 접근토큰은 유효기간이 24시간이고 **발급 빈도에 제한이 있다.** 매 요청마다 발급하면
즉시 차단되므로 반드시 캐싱한다.

- 메모리 캐시 + 만료 시각 보관
- 만료 임박(예: 10분 전)에만 갱신
- 갱신 실패 시 기존 토큰으로 재시도 후 명시적 에러

### `QuoteCache`

종목별 5초 TTL. 여러 탭이 동시에 폴링해도 KIS로 나가는 호출은 하나로 수렴한다.
호출 제한 초과가 감지되면 TTL을 자동 연장한다.

### `pricing` (순수 함수)

계산 로직 전체를 부수효과 없는 함수로 격리한다. **테스트의 핵심이자 TDD 대상.**

```ts
discountFromHigh(price, high52w)      // 정가 대비 할인율
changeFromPrevClose(price, prevClose) // 전일 대비 등락률
changeSinceAdded(price, addedPrice)   // 담은 뒤 변동률
lineSubtotal(quote, qty)              // 소계
cartTotal(items, quotes)              // 총액 (거래정지 종목 제외)
```

### `cart` (클라이언트 상태)

```ts
interface CartItem {
  code: string
  qty: number
  addedPrice: number   // 담은 시점의 현재가
  addedAt: string
}
```

localStorage와 동기화한다. **이 구조를 그대로 "주문 초안"으로 본다** — 2단계에서
체결 로직과 가상 현금만 얹으면 모의투자로 승격된다.

## 5. 종목 검색

KIS에는 종목명으로 검색하는 API가 마땅치 않다. 실무에서는 KRX 종목 마스터 파일을
내려받아 로컬에서 검색하는 방식이 일반적이다.

**결정: 종목 마스터(코드·종목명·시장)를 JSON으로 저장소에 두고 검색은 로컬에서 수행,
시세는 선택된 종목만 KIS로 조회한다.** 호출량을 아끼고 검색 반응속도도 즉각적이다.

구현 착수 시 실제 KIS API 목록을 확인해 이 결정을 재확인한다. 만약 쓸 만한 검색 API가
있다면 `PriceProvider.search()` 구현만 교체하면 되므로 다른 설계는 영향받지 않는다.

## 6. 화면

MVP는 두 화면이다. 상품 상세 페이지는 넣지 않는다 (YAGNI).

### 홈 / 검색

검색창과 결과 카드 그리드. 카드 구성:

```
      삼성전자  005930
  ~~85,000원~~   61,200원   [28% OFF]
        [🔥 세일중 ▼2.3%]
  ─────────────────────────
  수량 [-] 1 [+]     [담기]

  정가는 52주 최고가 기준
```

### 장바구니

행마다 종목명 · 수량 스테퍼 · 현재가 · 소계 · "담은 뒤 +1.2%",
하단에 총액. 5~10초 자동 갱신 토글을 둔다.

## 7. 쇼핑 은유 매핑

세 가지 기준가를 각각 다른 자리에 배치한다. 역할이 겹치지 않는다.

| 쇼핑몰 표현 | 주식 데이터 | 노출 위치 |
|---|---|---|
| 정가 (취소선) | 52주 최고가 | 상품 카드 |
| 판매가 | 현재가 | 상품 카드 · 장바구니 |
| 할인율 배지 | (52주최고 − 현재가) / 52주최고 | 상품 카드 |
| 🔥 세일 중 | 전일 종가 대비 하락 | 가격 옆 배지 |
| ↑ 가격 인상 | 전일 종가 대비 상승 | 가격 옆 배지 |
| 담아둔 사이 변동 | 담은 시점 가격 대비 | 장바구니 행 |
| 장바구니 총액 | Σ(현재가 × 수량) | 장바구니 하단 |

### 오해 방지

"52주 최고가 대비 30% 할인"은 저평가 신호처럼 읽힐 수 있으나 실제로는 많이 하락했다는
뜻일 뿐이다. 카드 하단에 **"정가는 52주 최고가 기준"** 을 항상 명시해 재미는 유지하고
오해만 걷어낸다.

## 8. 예외 처리

| 상황 | 동작 |
|---|---|
| 장 마감 | 현재가 = 종가로 고정, "폐장" 표시, 폴링 중단 |
| KIS 장애 · 토큰 실패 | 마지막 캐시 가격으로 총액 유지 + "시세 지연" 배너 |
| 호출 제한 초과 | 백오프 + 캐시 TTL 자동 연장 |
| 거래정지 · 없는 종목 | 장바구니에 경고 표시, 총액에서 제외 |

원칙: **총액이 화면에서 사라지는 것이 최악이다.** 시세를 못 가져와도 마지막으로 알던
가격으로 총액을 계속 보여주고, 그 사실을 명시한다.

## 9. 테스트 전략

- `pricing` 순수 함수 단위 테스트 — 할인율, 총액, 0 · 음수 · 결측값 처리
- `KisTokenManager` — 만료 · 갱신 · 갱신 실패 시나리오
- `QuoteCache` — TTL 만료, 동시 요청 수렴
- `MockProvider`로 UI 전체 플로우 테스트 (KIS 의존 없이)

## 10. MVP 범위 밖

명시적으로 만들지 않는다: 로그인 · DB · 모의주문 · 체결 · 포트폴리오 · 수익률 ·
미국 주식 · 차트 · 관심종목 · 상품 상세 페이지.

## 11. 확장 경로

**2단계 — 모의 주문**
장바구니(주문 초안)에 체결 로직과 가상 현금 잔고를 얹는다. 로그인과 DB가 함께 들어온다.
보유 종목과 수익률 화면이 추가된다.

**3단계 — 미국 주식**
`PriceProvider`에 `KisUsProvider`를 추가한다. KIS는 국내·해외 엔드포인트가 갈리고
거래소 코드(나스닥·뉴욕·아멕스)를 함께 넘겨야 하므로 어댑터를 별도로 둔다.
해외 시세의 실시간 여부(지연 시세 · 별도 신청)는 착수 시 확인이 필요하다.
